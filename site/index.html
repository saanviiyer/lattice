A reference manager that files your library by field and exports it for an LLM.

Import a .bib. One button groups the unfiled papers into collections named after research fields. Each collection lists what it is still missing. Export any set of them as chat context or a CLAUDE.md.

Local-first and open source. Grouping, naming and suggestions are computed from your own records, so it runs with no API key.

It reads titles, tags and abstracts, and names each collection after a research field rather than the two words the papers happen to share.

Where several clusters land on the same field, each keeps the field name and adds what separates it. Papers with too little in common are left unfiled rather than pushed into the nearest collection.

Each project lists what it is still missing

A project holds its papers, notes and open questions, and opens on a claim you could turn out to be wrong about. The list underneath is ranked: a premise before questions, questions before evidence.

Suggested projects carry the counts they came from

Two kinds: a method you have read applied to a domain you have read and never combined, and a question you gathered evidence for but never filed. Both are counted from the library rather than written by a model, so you can check one and disagree with it.

No model is called to organise your library

Grouping, naming, gap-finding and the suggestions are all computed from your records. Nothing about your literature is asserted that you cannot check in your own library.

Exports carry citation keys tied to papers you hold and instruct the assistant never to invent one. A question with no evidence attached is reported as a question with no evidence.

Two export formats

Chat context — premise, questions, papers with abstracts and any takeaways, and your notes. You choose how much of each paper travels, and the token count updates before you copy.

CLAUDE.md — rules first, and kept small because an agent reads it at the top of every turn. A 20-paper project is about 3,200 tokens.

Or connect the MCP server and skip exporting: six read-only tools over the live library, so nothing goes stale and nothing can be rewritten.

## How to use this
- Ground claims in the records below. If something is

- Cite papers by their key, exactly as written —
  `Rives2021biological`. Never invent a key, a title
  or an author.
- A takeaway is the user's reading of a paper. It is
  their position, not the paper's claim.

Getting started

1

Import a .bib or .ris

From Zotero, Mendeley or Google Scholar. Duplicates merge by DOI, arXiv id or title. Papers added by DOI fetch their own open-access PDF where one exists.

2

Press Group papers

Keep the collections that are right, drag the ones that are not, or clear them all and try again. The papers are never affected.

3

Write a premise for the ones you care about

One sentence, stated so it could turn out to be wrong. What is missing and what to work on next are both computed against it.

4

Export, or connect the MCP server

Copy into a chat, save a CLAUDE.md into the repository you are working in, or connect the server and skip the export.
